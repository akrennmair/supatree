# supatree — Agent Guide

`supatree` manages a set of git worktrees — one per repo — for a single
cross-repo issue. It is built on the shared packages of
[workbench](https://github.com/panamafrancis/workbench) (`pkg/config`, `git`,
`github`, `zellij`, `sandbox`, `mcp`, `setup`, `xdg`, `testutil`, `version`)
and is independent of it at runtime: neither reads the other's files.

## Build & run

```sh
make build          # supatree binaries under dist/
make install        # go install ./cmd/supatree
make ci             # fmt + lint + vet + test
make e2e            # build + run scripts/e2e-supatree.sh
go test ./...
```

## Working across both repos

Workbench's `pkg/*` is not a stable public API; supatree is its one outside
consumer. A change that touches a shared package is two PRs, in order:
workbench first, then here, bumping with a pseudo-version
(`go get github.com/panamafrancis/workbench@<merged-sha>`) — tags are cut only
for workbench's own releases. For local development, a `go.work` that `use`s
both checkouts builds against your unpushed workbench changes; after a bump,
`go mod tidy` with `GOWORK=off` must succeed before pushing. Shared-package
discipline (GitHub quota, the PR cache's single writer, the zellij quirks) is
documented in workbench's AGENTS.md and applies here unchanged.


`supatree` manages a set of worktrees — one per repo — for a single cross-repo issue. Files follow XDG (see "Layout" below).

**Model.** A *stack* is a git repo (`supatree scaffold`) holding `supatree.yml` (`members:` alias → git URL, plus `deps` edges), `AGENTS.md`, and `scripts/`; it can live anywhere. A *supatree* is a worktree of that stack repo at `~/supatree/trees/<name>/` on branch `st/<name>`, with each member repo checked out under `repos/<alias>/` on branch `st/<slug>/<alias>` (slug starts as the city name; `rename-branch` changes it). Aliases are stack-local.

**Supatree is independent of workbench at runtime.** It never reads workbench's config or any other workbench file; the only link is the Go module. Its own `config.yml` holds `models` (`supatree.DefaultModels()`: `config.DefaultModels()` with claude on the `supatree-agent` profile) and per-repo personal `repos` settings (`copy_files`, keyed `host/owner/repo`).

**Repo cache (`repos.go`).** Supatree owns its clones: one per remote at `~/supatree/repos/<host>/<owner>/<name>` (`CacheKey`; a local path or `file://` URL keys under `local/`), from the URL the spec gives. The path *is* the registry. `github.ResolveRemote` resolves an ssh-config alias to its real host, so `git@github-work:o/r` and `git@github.com:o/r` share a clone; `RepoRefFromRemote` is now a thin wrapper over it. `Config.ResolveMember(alias, url)` is the only place supatree clones (temp dir + rename, under a per-key lock, stdin closed); `cachedClone` resolves without cloning. Teardown reads the clone from the worktree itself (`cloneOf`, via the git common dir), so a member that has left the spec can still be removed. Never adopt a clone supatree did not make.

**Spec format (`spec.go`).** One format: `members` is a map. A list-form spec (the old alias format) fails with `ErrOldSpec`, which says to map each alias to its URL; there is no dual-form parser. `Spec.Aliases()` is sorted, and `OrderedMembers` topo-sorts that.

**Setup hook (`setup.go`).** `RunSetup` runs the stack's `scripts/setup` once per tree, at creation, after members and `copy_files`, before any tab: stdin closed, `GIT_TERMINAL_PROMPT=0`, output to `.supatree/setup.log`, recorded in `meta.SetupAt`/`SetupErr`; failure is a warning. There are no per-member hooks, and `sync` never re-runs it.

**Stack and repo commands (`stack.go`, `supacmd/stack.go`, `supacmd/repo.go`).** `stack new` (= `scaffold`) takes members from `--repos`, `--from <dir>` (reads each checkout's origin only — the checkout is never used), `--from-org` (gh, skipping archived and forks) or a picker over the cache; `stack add/rm/dep` edit `supatree.yml` through `editSpec`, and `stack upgrade` edits `AGENTS.md` (`UpgradeAgentsMD`), both through `editStackFile`, which commits **only** that one file and refuses when it has uncommitted edits of its own; `stack clone` registers a teammate's stack, fills the cache and prints its `scripts/setup`. `repo ls`/`repo rm` work on the cache; `rm` refuses while `CacheUsage` finds a tree on the clone (paths compared resolved: git reports `/private/var` for `/var`). The PM gets `stack_add`/`stack_rm`/`stack_dep`, gated on mutation autonomy like `new_tree`; **`New` builds every tree from the stack's origin, so an edit is published as part of making it (#17)** — and who makes it decides what it may trust (`StackEditMode`). The stack checkout is writable by the PM and, through the shared `.git`, by every tree agent, so its remotes, hooks and unpushed commits may all be agent-written. Publishing goes only to an origin a human pinned in supatree's config (`Stack.Origin`): `stack clone` pins the URL it was given, `stack pin <stack> <url>` pins one typed in — **never one read from the checkout**, whose remotes an agent can rewrite. **`ByHuman`** (the CLI) and **`ByWatcher`** (the PM's `OpStack`) both publish to it, and an unpinned stack's edit is committed locally with the pin command in the answer. Neither runs network git in the checkout. Either way the edit is made in a private clone under `StackEditsDir` (`publishStackEdit`), and exactly that one commit is pushed to the origin's default branch — never anything found unpushed in the checkout. A branch that refuses the push gets the edit as `supatree/stack-edit-<time>` with a pull request (`openStackPR`). The checkout is not fast-forwarded (that too would run git where an agent writes); the answer says to pull. Every network step goes through `netGit`: bounded at `stackNetTimeout`, never prompting, since one hung push would stall the watcher's op queue. A PM edit to an unpinned stack runs in the PM's own sandbox as a local commit (**`InSandbox`**) that says so. A member the PM adds must match `isRemoteRepoURL`, an allowlist of `https://host/owner/name`, `ssh://git@host/owner/name` and `git@host:owner/name` — each segment starting with a letter or digit, and the host one the cache already holds clones from or github.com, so the watcher's credentials never fetch from somewhere only the PM chose — **and under a host and owner the stack already uses** (`ownerVouchedFor`: an existing member's, or the pinned origin's, judged on the private clone's spec, never the checkout's), since your credentials reach every private repo you can and the PM would otherwise pick any of them for the watcher (or a later tree) to clone into a cache it reads. A repo under a new owner is added from the terminal. (`CacheKey` refuses `.`/`..` segments besides.) The PM-side autonomy gate is a consent boundary, as for `remove_tree`'s `force`, and is not re-checked in the watcher: a local path (git reads `/dir/x:o/r` as one, though it parses as host:path) would have the watcher copy any repo on the machine into the cache, which the PM reads. `StackEditResult.Live` says whether the next tree will see the edit; the CLI and the tools fail when it will not. A review tree also maps its PRs against the spec it was actually built from (`finishCreate`), refusing — and naming an unpushed edit (`unpublishedMember`) — rather than creating a tree missing the PR's member. Sidebar `S` names a stack and runs `stack new` in a `supatree-stack` command tab that waits for enter, the name passed as an argument, never spliced into the script.

**Layout.** Config `~/.config/supatree/` (`config.yml`, `schedule.yml`); state `~/.local/state/supatree/` (`trees/<name>/`, `pm/`, `roster/` (the PM list tree agents may read), `ledger/`, `outbox/`, `requests/`, `archive/`, `logs/`, `ui.yml`, locks, `watch.lock`); cache `~/.cache/supatree/` (`agent/` — PR, comments and recall caches, the only part an agent may write — plus `layouts/`, `last-status.json`, `notify-state.json`, `schedule-state.json`); workspaces `~/supatree/{trees,stacks}`. The queues are directories, not files, so a sandbox is granted a directory: rotation and drains replace files, and a file grant follows the old inode on Linux. `supatree.EnsureLayout()` creates every granted dir up front (nono refuses a grant on a missing path).

**Discovery.** The config lists stacks + defaults; `ui.yml` holds the sidebar's fold state (`uistate.go`). **Per-tree state lives outside the tree**, in `<state>/trees/<name>/` (`meta.yml`, `agents.yml`, `info.md`, `board.md`, `mail/`, `ops/`); the tree root's `.supatree` is a symlink to it (`LinkState`, called by `Meta.Save`), so `.supatree/info.md` reads as it always did. `StateDir(root)` derives `<state>/trees/<basename>` and **never follows the link**; it is the only function that knows. `supatree.List` scans `<state>/trees/*/meta.yml` and `rootFor` puts each tree under the trees base — **never** at `meta.Root`, which is informational. `Remove` and `rollback` delete the state dir as well as the root — state left behind is a tree `List` keeps reporting. Tree creation adds `/.supatree` and `/repos/` to the stack's `info/exclude` (`excludeFromStack`): a `.supatree/` gitignore pattern matches a directory, not the link.

**Package layout.** `pkg/supatree/`: `paths.go`, `config.go` (config), `repos.go` (repo cache), `setup.go` (scripts/setup), `sandbox.go` (profile + grants), `ops.go` (watcher-run tree operations), `spec.go` (supatree.yml), `meta.go`, `deps.go` (`TopoSort`), `instance.go` (`LoadInstance`/`List`/`Get`), `create.go`, `sync.go`, `remove.go`, `rename.go`, `agents.go`, `contextfile.go` (info.md + scaffolded AGENTS.md), `agentsmd.go` (recognising and upgrading old scaffolded AGENTS.md), `scaffold.go`, `status.go` (the activity state model), `uistate.go` (sidebar fold state), `prfetch.go` (shared PR fetch), `review.go` + `post.go` (review mode), `mcp.go`, `tui/` (the `supatree ls` sidebar), `dash/` (the `supatree dash` dashboard). CLI in `supacmd/`, entry `cmd/supatree/main.go`.

**Status model (`status.go`).** `Status(insts, cache, opts)` derives a `Summary` from local git plus the on-disk PR cache — it never calls GitHub, so any UI may call it freely. Keep the derivation pure and testable: `localState` does the git I/O, `memberState` and `rollup` are pure functions over it and are what the tests cover. Member states run `absent → idle → wip → pushed → draft → open → changes|approved → merged|closed`; the tree rollup is the least advanced member that still has work, with `Blocked`/`Dirty`/`Stale` as orthogonal flags and `TreeDone` meaning "reap this tree". Two states sit off that ladder: `foreign` (the branch checked out is not the one the tree derives — every other number would be measured against a branch the worktree is not on, so `localState` stops collecting them and `rollup` sets `Foreign` instead of ranking it) and `in-review` (a review tree's member, ranked alongside an open PR). `memberState` takes `tracked`, because a review tree holds every member of its stack and the repos the change does not touch must fall out as `idle` — left `in-review` they would pin the rollup below `reviewed` forever. Local git runs concurrently (`statusWorkers`) because a dozen supatrees is a few hundred git processes.

**Review mode (`review.go`, `post.go`, `supacmd/review.go`).** `supatree review <pr-urls…>` builds a *review tree*: `Meta.Mode = reviewing`, `Meta.Review` maps each member alias to the `ReviewRef` (repo, number, URL, head SHA, head ref, base) it is checked out at, and `createMember` starts it from `refs/pull/<n>/head` — the only ref that reaches a PR opened from a fork — on a tree-local `review/<slug>/<alias>` branch. The branch prefix is not cosmetic: the author's branch name cannot be checked out twice in one clone, a detached HEAD would make `CurrentBranch` report the literal `HEAD`, and a tree-local ref is unambiguously supatree's to delete.

**A review tree is keyed on the pull request, not the branch.** `Member.CacheKey()` returns `pr:<repo>#<n>` there — the PR cache is one flat map across every repo and tree, which is safe for `st/<slug>/<alias>` only because that name embeds the alias, while two members of one cross-repo change routinely share a branch name. `FetchTargets` therefore pins review members to their PR (`github.Target.Ref`), which exempts them from the unpushed-branch skip (their branch has no origin ref *by design*) and makes `Sync` match them by number only — a head lookup on a tree-local branch is a guaranteed-empty request. `NewReview` seeds the cache with number+URL and no status so the first round has something to resolve. **`LoadInstance` attaches `Member.Review` only while the mode is still `reviewing`** — `ForkReview` keeps `Meta.Review` as provenance, and carrying it past the fork would key the forked tree's members on the *author's* PR forever.

**The authoring commands refuse** (`refuseAuthoring`, `ErrReviewTree`): `rename_branches`, `create_pr`, `create_prs`, `supatree rename-branch`. The refusal names the alternative, because the agent that reaches it was told by its own instructions to rename before opening a PR. `contextfile.go` renders `reviewTmpl` instead of `infoTmpl`, and the review *craft* lives behind `docs topic: review` rather than in the generated info.md — it is generic, long, and identical in every tree, so it must not load into every context by default.

**`review_post` is the one outward-facing tool.** It needs the `outward` permission — off at every level, `auto` included, **except in a review tree**, where `Resolve` defaults it on (`Config.ReviewOutward`, `review_outward: false` to withhold; a tree's own `outward` still wins). Posting the review, APPROVE included, is what a review tree is for, and every other authoring verb there is already refused and `outwardDenied` refuses rather than falls through when the config cannot be read. It refuses again when `headMoved` — cached `PRInfo.HeadOID` against the recorded `ReviewRef.Head` — says the author has pushed, since GitHub marks an inline comment outdated the moment it lands on a passed commit. `review_refresh` / `supatree review refresh` re-fetches each head and `git reset --hard`s the worktree onto it, **never** over uncommitted work (review notes are not disposable). `supatree review add <pr>…` / `review_add` (the tree's agent, or the PM with `tree`) adds pull requests to an existing review tree (#12) — `AddReview` maps each against the tree's spec, moves an idle member onto the PR head (refusing over uncommitted work or commits of its own), or creates the member at it, records it in `Meta.Review`, seeds the PR cache and mails the agent; review.md and every other review state are kept, and the state goes back to `reviewing` on the next round while an added PR is open. The MCP path is `OpReviewAdd` in the watcher (a new member may need a clone, resolving a PR needs gh), allowed from the PM or from the tree's own state dir for itself, which vets the tree's spec as a sync does; an added PR's event reads "added for review", not "opened". A member created this way is readable by a running agent but, like any member synced in later, committable only after a restart. `supatree review fork` renames every member onto `st/<slug>/<alias>` (phased with rollback, like `RenameBranchSlug`) and records each PR's head ref in `Meta.Base`, so `createOnePR` passes `--base` and the change arrives as a proposal on the author's PR rather than a rival against main.

**A review tree's merge is the author's milestone.** `Event.Mode` is stamped on every event so the append-only ledger can never be reinterpreted; `History` counts those on a `Reviewed` axis and refuses to add them to `Merged`. Review trees are never `Blocked` (failing checks are the author's problem, requested changes are your own review landing), finish as `TreeReviewed` rather than `TreeDone`, and report `author_pushed` — the one transition that invalidates a review in progress, and the only one diffed outside the lifecycle state.

**Teardown deletes only the branch the tree created.** `removeMember` takes the branch it *owns* and runs `git branch -D` on that alone; a member found on anything else is reported and left in place, because a `gh pr checkout` in a member worktree would otherwise have the author's branch destroyed by an ordinary `supatree rm`. There is an e2e case for exactly this.

**Worktrees are created through `safegit.go` (#21).** The stack and every member's base clone are agent-writable (a tree shares the stack's `.git`; a tree agent commits in the clones), and the watcher creates worktrees in them. `HardenGit` pins the fixed-name command settings; `RequireSafeRepo` refuses the rest, but checks once while git re-reads the config when it runs. `addWorktree` therefore pins every filter the checkout could run — each name in the start commit's `.gitattributes` files and in `info/attributes` — to a pass-through on the command line (outranking repo config whenever it is written), refuses a name that could smuggle a value into the `-c` key, and re-runs `RequireSafeRepo` as late as it can for the keys nothing can pin (`include.*`, `url.*`). `createWorktree`, given the stack's pinned origin, takes nothing from the checkout: the default branch and its commit come from `ls-remote` on the URL, the tree starts at that commit, and an unreachable origin is an error — never a fallback to the agent-writable `origin/<default>` ref, which would let an agent choose every new tree's starting commit, `AGENTS.md` included. Global and system attribute files are switched off for the checkout, and `.gitattributes` is matched case-insensitively. Those checks leave a milliseconds-wide race (`info/attributes` plus a filter definition, or an unpinnable key, written between the last check and git's start), so **the steps that run configured programs are confined (`gitjail.go`)**: every fetch (`fetchGit`, `fetchRef`) and the `worktree add` checkout run under `nono run` with the default model's profile — the agents' own — with the repository readable, its common git dir and the new worktree (created empty first) writable, and a local-path origin readable only when supatree holds that URL (the stack's pinned origin, a member's spec URL), never one taken from the repository's config. Whatever an agent planted then runs with no more than the agent already had. A jail with no profile refuses rather than run git unconfined; inside a nono sandbox already (`NONO_CAP_FILE`, as in tests and nested runs) git runs directly, confined by that one. Read-only plumbing (rev-parse, ls-tree, cat-file, config) stays unconfined, as do the watcher's status rounds: they run no configured program, and a nono start per call (~0.7s) would cost the rounds dearly.

**Removal stops what the tree launched, not just its tabs (#2).** `CloseTree` deletes every `<tree>:*.kdl` layout (an agent no longer in `agents.yml` used to leave one per removal), closes the tree's tabs in every session (retrying once past an open circuit breaker), then `StopAgents` whatever of the tree's is still in the process registry — closing a tab only hangs up, and an agent that survives the hangup ran on paneless. Its warnings reach `remove_tree`'s answer (`OpHooks.Removed` returns them). `supatree rm` on a name that is already gone still runs it. The watcher's `SweepRemoved` catches the rest every round: layouts and processes of trees with no trace on disk (`KnownTreeNames` — never `List`, which skips a tree it cannot parse), and tabs only of trees in the archive, so a tab that merely matches no tree is never closed.

**The process registry (`procs.go`).** `agent-exec` writes `<state>/procs/<pid>.json` (tree, agent or PM, zellij session, session id, nono's pid) when it starts nono and removes it when nono exits; on a hangup it passes the signal on and escalates — SIGTERM, then SIGKILL of nono's whole process tree, since the agent is nono's child and outlives it. A record is trusted only while `ps` still shows that pid as an agent-exec (pids are recycled). `supatree ps [--orphans]` and `supatree kill` read it, and the PM's `stop_agent` queues `OpStop` for the watcher: no sandbox may run `ps` or signal a process.

**PR fetching (`prfetch.go`).** `FetchTargets` + `FetchPRs` are supatree's single entry point to `github.Sync` (see "GitHub quota discipline" above): `FetchTargets` lists every checked-out member (keyed by `CacheKey()`, review members pinned), and `FetchPRs` runs the round inside `Cache.TryMutate` — or the blocking `Mutate` when forced, since a person is waiting. The sidebar, the dashboard, the watcher and `supatree status --refresh` all call them; do not write a third copy, and do not add a poller that bypasses them. Both callers run the whole thing inside a `tea.Cmd`: selecting targets is one git process per member, which visibly stalls a UI if done on the main loop.

**Autonomy (`autonomy.go`).** `Config.Resolve(meta)` folds the workspace default and the tree override into a `Permission`. The workspace default is not convenience — autonomy lives in per-tree `meta.yml`, so without it nothing governs `new_tree`, whose tree does not exist yet to carry a level. **Outward-facing is a second axis, not a higher level**: `auto` grants mutation and deliberately not a public voice, and there is a test asserting that. **The level gates the unasked case only** — `AsAsked` carries the PM's assertion that the human asked for this action in this turn, and `AllowsMutation` honours it below `auto`, because the word in `meta.yml` has always meant "unasked" and a gate that also refuses a direct request turns the default level into a wall in front of the commonest interactive verb there is. It does not lift `off` (report-only is not a level you talk your way past) and it cannot hold on a `Scheduled` turn (nobody is in one to have asked) — both have tests. Trust it the way `remove_tree`'s `force` is already trusted: this is a consent boundary, the sandbox is the security boundary, and the PM is the only thing that knows who asked. `AsScheduled` caps a scheduled turn at `nudge` (nobody is watching) unless the job opts in, and returns a copy rather than mutating. `Deny` must name the setting a human would change; a bare "not permitted" is useless.

**Memory (`memory.go`).** `notes/` in the *stack repo*, not a store of our own: diffable, blameable, reviewable, team-shared, and readable by supatree itself. `Recall` is substring search and `History` is exact derivation from the ledger — keep that split, and keep the PM instructed never to answer a status question from `recall`. `isNote` excludes the scaffolded README, which otherwise matches every query with its own examples (found by a test). `MemorySummary` is the injection budget: a hard cap in `info.md` with everything else behind `recall`, because read-time is what has to be rationed. `logRecall` records hits *and* misses from day one — without it the 30-day kill criterion is unmeasurable. `sandbox.ArchiveSessionCache` runs before `ClearSessionCache` on reap: move now, distil later, and never block a removal on it.

**Schedule (`schedule.go`).** `Due(jobs, state, evs, now)` is pure and carries three rules that are each a table test: seed an unseen job id rather than treating "never fired" as overdue; coalesce a missed window into **one** fire (anacron, not cron); and suppress a job with nothing to say (`when: events_since_last` is the default). A *suppressed* fire still advances `LastFired`, or the job is due on every tick until something happens and then fires at the wrong time. `At:` compares against today's occurrence rather than counting elapsed time, which is what keeps the clock going back from manufacturing a second 09:00. The scheduler runs inside the watcher — same loop, same singleton lock, no new poller — and fires by appending to `requests.jsonl`, so a scheduled job and a pressed `m` arrive identically.

**Three MCP gates, not two.** `recallTools` are ungated (memory only one caller can read is memory half the system cannot use); `dualTools` (`agents`, `message_agent`, `inbox`, `pr_comments`) accept `SUPATREE=1` *or* `SUPATREE_PM=1` and resolve their supatree from an optional `tree` argument, falling back to the environment; `pmTools` require `SUPATREE_PM=1`. The dual set exists because the PM is rooted in no supatree — without it the PM could see every tree and talk to none of them, which is most of the point of having one. `messagingDenied` enforces `AllowsMessaging` for the PM only: an agent messaging its own siblings is collaboration, not autonomous action.

**The ledger is bounded and degrades softly.** `AppendEvents` rotates *before* appending — rotating afterwards renames away the file the new events just landed in — keeping exactly one generation (`events.jsonl.1`), which `ReadEvents` reads first so the result stays a timeline. A torn JSON line costs that line; a line longer than the scan buffer ends that file's read and returns what came before. Both matter because four readers depend on this one call (sidebar, dashboard feed, schedule gate, `History`) and a hard error would take all four down together. The sidebar reads it in a `tea.Cmd`, never on the main loop: one sidebar runs per Zellij tab.

**PM agent (`pm.go`, `requests.go`, `supacmd/pm.go`).** Rooted at `<state>/pm` (its own state dir: `StateDir(PMDir())` is `PMDir()`), tab `PMTab` (reserved like `DashTab`). **One PM is one process (#1).** `OpenOrFocusTab` focusing a live tab was never enough: the tab check and the open are seconds apart, and retries in that window each started a PM on the same session, leaving all but the last running with no pane. So the open runs under a per-tab lock (`openLockPath`, held only for the open itself — the same lock covers `OpenRootAgent`), and a PM the process registry shows running is focused, or refused with its pid when it has no tab here. A tab is replaced only when zellij reports its agent pane exited (`LivenessDead`), never on an unreadable listing. Every PM and agent open is logged to `logs/launch.log` with what it came to and who asked (#3). The PM reads the git dir of every clone in the repo cache (`cachedCloneGitDirs`), not just those of trees alive at launch, so a new tree on a known repo never needs a relaunch — and never a clone's working tree, which holds the gitignored files `copy_files` hands out. The lock file name is the tab hex-encoded, and `TakeLaunches` drops queue lines with invalid names: the PM's sandbox writes the launch queue directly. **The PM config repo (`pmconfig.go`, #11)** is the versioned part of how PMs behave, apart from their runtime state: a git repo the human registers with `supatree pm config <path|url>` (`Config.PMConfig`; refused under the stacks, the trees or the state root, which agents write), or creates with `pm config --init` (`InitPMConfig`: always `DefaultPMConfigPath`, overlap-checked before anything is made, and scaffolded with only a README and `pms/` — no `AGENTS.md` or `.claude/`, since either would change the PMs and a `.claude/` would move theirs aside). `ScaffoldPM` appends its `AGENTS.md` and one `## Only if you are the <name> PM` section per `pms/<name>/AGENTS.md` to the generated instructions — every PM shares one home and one AGENTS.md, so per-PM text is keyed by name, which each PM reads from `SUPATREE_PM_NAME` — and links `.claude/` into the PM's home on every launch — anything else standing there (the home is the PM's to write) is moved aside under a timestamped name and logged. `pms/<name>/settings.json` reaches that PM alone as `--settings` (claude models), the name validated and the path held inside `pms/`, since `pms.yml` was PM-writable before #23. **The registry (`pms.yml`) lives in the state root (#23)**, not in `PMDir()`: the unsandboxed sidebar, CLI and watcher act on it (sessions, top PM, model), so the PMs only get the roster published from it, read-only. A registry left in `PMDir()` from before is migrated once (`migrateLegacyPMs`: invalid or duplicate names dropped, odd session IDs replaced, `model` and `config_at` reset since a PM could have chosen its own nono profile, the default PM put back on top; resets are logged to `launch.log`) and removed; one that reappears there is never read, and `doctor` warns. Code running inside the PM's sandbox resolves PMs with `RoutingPMs`/`ResolvePM`, which fall back to the roster on a permission error. The repo's path is stored resolved and re-checked at every launch (`usablePMConfig`), so a link swapped after registration is not used. `PMGrants` *reads* the repo and never allows it: a PM editing the skills and settings that govern it would be a PM widening its own permissions. Each launch records the repo's commit in `pms.yml` (`ConfigAt`), and `pm ls` flags a PM running an older one. Gated by a *second* MCP gate: `pmTools` require `SUPATREE_PM=1`, and the PM deliberately does **not** set `SUPATREE`, so the tree-scoped tools stay hidden rather than resolving nothing and failing confusingly.

**Sandboxes (`sandbox.go`, `pm.go`).** Two layers, both nono's. The static profile, `supatree-agent` (`AgentProfile`, written by `supatree init` into nono's profile dir; the default `claude` model points at it via `supatree.DefaultModels()`), grants the toolchain, supatree's config **read-only** and `AgentCacheDir` — never the state root (its `pm/` queues are executed by the unsandboxed watcher) and never the rest of the cache (zellij runs `layouts/` unsandboxed). Everything tree-specific is a per-launch flag: `TreeGrants` (root agent: tree root, its own state dir, the stack's git common dir, each member's base-clone git common dir — this tree's only), `MemberGrants` (member agent: that worktree + its clone's git dir + the tree's state; tree root read-only), `PMGrants`. `sandbox.Grants` carries `Allow`/`Read`/`AllowFile`/`ReadFile`; `supatree sandbox-args <tree> [--pm]` prints the flags for audit, and the e2e enforcement case runs a probe under exactly them.

`PMGrants` is the security boundary and has tests asserting it: allow `<state>/pm`, `<state>/trees` (every tree's state, one directory — a tree created after launch needs no relaunch), `outbox/`, and the stack repos; read the trees base, `ledger/`, `requests/` and the members' clone git dirs; never anything inside a tree. `pm_model` selects the models entry, which is how the PM gets a *different* nono profile from the coding agents — its risk is in network and credentials, not execution.

**Never trust what an agent can write.** A tree's agents can write its root (the spec, the `.supatree` link), its state (`meta.yml`, `ops/`), and the git dirs of its stack and member clones. Anything unsandboxed that reads those must treat them as hostile: aliases are validated in `parseSpec` (they become paths that `Remove` deletes); `StateDir` and `rootFor` derive paths from names; a tree's own sync request may only bring in repositories its stack's checkout or the cache already has (`vetTreeSpec`); and every unsandboxed command calls `git.HardenGit()` (hooks, fsmonitor and ext transport off; ssh command, askpass and credential helpers pinned to the user's global config via `GIT_CONFIG_*`), while `git.RequireSafeRepo`/`RepoConfigRisk` refuse a repository whose local config sets what cannot be pinned (filter drivers, includes, `url.*`, uploadpack…) — in create, `ResolveMember`, teardown, `editSpec`, and the status round.

**Tree operations go through the watcher (`ops.go`).** `new_tree`, `remove_tree` and `sync` write worktrees, clones and branches no sandbox is granted, so the MCP tool writes an `Op` into `<dir>/ops/<id>.json` and waits (`RequestOp`, `opTimeout`) for `<id>.result`; the watcher's `runOpsLoop` (its own goroutine, 1s tick, one op at a time) claims by rename (`ClaimOps`), runs (`Config.RunOp`) and answers (`AnswerOp`). **Where a request is written authorizes it** (`authorizeOp`): `PMDir()` may ask for anything; a tree's state dir only to sync that tree. A request nobody claimed by the deadline is withdrawn so it cannot run later; a claim a dead watcher left is answered "interrupted" on the next start (`AbandonInterrupted`), never re-run — re-running a create makes a second tree. Autonomy checks stay in the PM tool, before queuing.

**The watcher nudges a PM with mail (`pmnudge.go`), opt-in via `pm_nudge: true`.** Off by default because the text lands wherever the prompt is, a half-typed draft included. With it on, `pmMailTick` — the watcher's 2s launch tick — runs `NudgePMs` right after `ForwardPMMail`, so a reply forwarded now is nudged now. It types the fixed `PMNudgeText` into the PM's pane through `AgentPane` (`agentpane.go`) and `zellij.SubmitToPane`, the same path `wakeAgent` uses: a pane counts only if it runs nono, directly or behind the `supatree agent-exec` shim that every supatree agent pane actually shows as its command (`zellij.AgentPane` recognises only bare nono, and so found no supatree agent at all) — never "the only other terminal", which can be the user's shell, and the calls are bounded and behind the circuit breaker. The session comes from the PM's `ProcRecord`, since the watcher is in none. `pm-nudge.json` (cache, outside the PM's sandbox) records per PM the **queue byte offset** just past the newest request it was nudged for (`pendingRequestsEnd`, `nudgeDue`, with the read offset's truncation rule) — never the request's `At`: a forwarded message keeps the time its tree agent wrote into it, older than the last nudge (never nudged) or decades ahead (nothing after it nudged). Mail for another PM does not move a PM's offset. A PM with no live process, a dead session or no certain agent pane is skipped **without** advancing the state, so the next tick retries; a submit is attempted at most once, its state advancing even on failure, since a half-delivered nudge retyped leaves the text twice. Nothing due costs no `ps` and no zellij call. **Focus is not checked**: `FocusedTab` names the client's current tab, which a PM tab left open in a backgrounded terminal always is, so the check suppressed nearly every nudge; the opt-in is the guard. The nudge is a convenience: the PM is still told to call `requests` every turn.

`requests.jsonl` is the inbound queue: anything that can append to a file can reach the PM, which is what lets Go processes talk to an agent at all. The read cursor is a **byte offset**, not a timestamp — two requests in the same nanosecond are two entries and a timestamp cursor would silently drop one — stored with the file size it was valid for, so a truncated queue is re-read from the start rather than seeked past the end. `CommitRequests` is called *after* the requests are handed over, so a PM that dies mid-turn re-reads rather than loses.

**Hands-off launches (`launch.go`, `supacmd/watch.go`, `supacmd/open.go`).** The PM cannot open a tab — it runs inside nono — so `new_tree start:true` and `start_agent` go through `startAgent`: register the agent (`EnsureAgent`, so the launch resumes by a known session id and `message_agent` can find it), `Deliver` the brief to its mailbox (a review tree with no brief gets `DefaultReviewBrief`), then `QueueLaunch` onto `<state>/pm/launch.jsonl` — in `PMDir` because that is the one place the PM's sandbox is guaranteed to write — stamped with the PM's `ZELLIJ_SESSION_NAME`. **Brief before launch, always:** `OpenRootAgent` appends `KickoffPrompt` (via the model's `prompt_args`, `{prompt}` substituted by `sandbox.AppendPrompt`) only when `HasMail`, so the order is what makes the agent start working instead of sitting at an empty prompt. The kickoff is fixed text by design — the brief rides in the mailbox, so nothing the PM wrote (or relayed from a PR) reaches a command line or a KDL layout. The watcher takes from the queue on its own 2s tick (`launchPollInterval`; one `stat`, no GitHub) and runs each launch as a child `supatree open --session <s> --background`, reusing the ordinary open path; `--background` (`OpenOptions.Wake`) records the focused tab just before the tab is opened (`prevTab`: `zellij.CurrentTab`, falling back to `FocusedTab`, retried — a lone `dump-layout` once came back marking no tab focused) and `keepFocus` goes back to it — outside the open locks, watching for `focusSettle`, since zellij focuses a new tab when it applies its layout, which can land after `new-tab` returns — so a launch nobody at the keyboard asked for does not take the terminal away. One launch's watch and the next one's `prevTab` share `focusLockPath`, or the second would record the first's new tab as where the human is. Every watch is traced to `launch.log` (`focus <tab>`). The child prints its outcome through `OpenOptions.Opened` *before* the watch, and the watcher (`runBackgroundOpen`) answers at that line and leaves the child to finish, so the serial launch queue never waits out a watch. **It takes only what `LaunchGate` admits** (#1): at most `max_running_agents` (default 3, 0 = none) agents busy at once, busy meaning a live tab whose transcript grew within `BusyWindow` or one the watcher started within it; waking a live agent costs no slot, and the rest stay queued in order (`TakeLaunches`). **A running agent is woken, not just focused** (#15): an idle interactive agent takes no turn, so mail left for it went unread forever. `--background` sets `OpenOptions.Wake`, and `OpenRootAgent` types the fixed `WakePrompt` into its pane (`AgentPane` + `zellij.SubmitToPane`) when mail waits — never into a pane it cannot be sure is the agent. The child prints its `LaunchOutcome` (`OpenOutcomePrefix`), the watcher writes it to `LaunchResultsDir()/<id>.json`, and `startAgent` waits up to `launchWait` for it, so `start_agent` says started / woken / only mailed / still queued instead of "queued" for all four. `agents` reports a bus address only when the agent's model has `agent_name_args` (`busAddress`): without them the agent ran under a name of Claude's choosing. Replies go the other way: a tree agent's `message_agent agent=pm` lands in *its own tree's* mailbox (the only one it can write), and `ForwardPMMail` — run on the watcher's 2s launch tick, never inside `watchRound`, whose GitHub fetch and early returns once stranded replies for a day (#6) — moves it into the request queue, deleting each message only after it is queued.

**Agent addressing and mail (`agents.go`, `mail.go`).** `AgentAddress(tree, agent)` is `st-<tree>-<agent>`, deliberately not the `<tree>:<agent>` zellij tab identity — a colon has no business in a bus name and the namespaces should be free to diverge. It is **persisted** on the `Agent`, not derived at read time: a supatree renamed after an agent launched cannot rename the running process, so the stored value is what that agent actually answers to. Addresses match **exactly** — verified against claude 2.1.261 (2026-09-20), where `--name st-probe` appeared on the bus as exactly `st-probe` while directory-derived names all carried a two-character suffix. Do not reintroduce prefix matching: `st-canberra-main` is a prefix of `st-canberra-main-2`.

`Model.AgentNameArgs` carries the flag (`{agent_name}` substituted by `sandbox.BuildNamedAgentNonoArgs`); a model without it gets no name flag invented for it. `substituteTokens` replaces tokens anywhere in an argument, so `--name={agent_name}` works as well as a separate argument.

**The mailbox is the contract; the bus is an optimisation.** `Deliver`/`Mail`/`Drain` write one file per message under `.supatree/mail/<agent>/` — one file rather than an appended log because delivery and consumption are separate processes, and deleting exactly the file you read needs no read-modify-write of a shared log. A torn message is dropped by a *consuming* read only, so one bad file cannot wedge an inbox forever. Go can write a mailbox; Go cannot use the bus, and neither can a non-Claude model — so anything that treats the bus as the primary channel is wrong and will break the first time either is absent.

**Review comments (`pkg/github/comments.go`, `pkg/supatree/comments.go`).** `PRComments` is the one path that spends a *second* GraphQL query shape per PR — thread resolution (`reviewThreads { isResolved }`) exists nowhere else — so it is on-demand only and must never be called from a poll. Comments and reviews ride along in the same query rather than costing two more calls, and the `last:` windows are bounded so one pathological PR cannot eat the budget. `RepoSlug` reads owner/name from the local origin remote rather than `gh repo view`, because every API route to the same answer spends from the bucket this package exists to conserve. `supatree.Comments` caches on `(branch, number)` and validates against the PR's `updatedAt` — GitHub moves it on any activity, so an unmoved timestamp proves nothing has been said. It takes the *blocking* `WithFileLock` rather than the pollers' try-lock: somebody explicitly asked, so waiting out another round beats returning nothing. A rate-limit response arms the same persisted `SetRetryAfter` cooldown every other fetch path observes.

**Events and the watcher (`events.go`, `notify.go`, `supacmd/watch.go`).** `supatree watch` is the only background poller and a singleton by `config.TryFileLock(WatchLockPath())` — the lock is held for the daemon's whole life, so a concurrent `--once` gets `ErrLockBusy` and **must exit 0 quietly**; that is what stops a cron entry double-fetching, not an error path. Because that daemon outlives every upgrade, it watches its own executable (`binaryWatch`) and `syscall.Exec`s the new binary once the file has been stable for two rounds; the flock goes with the old image (Go opens files close-on-exec), and `opsMu` keeps the exec out of the middle of an op. It fetches through `FetchTargets`/`FetchPRs` like everything else, so it adds no new GitHub load.

`Diff(prev, cur Summary) []Event` is pure and takes its timestamps from `cur.At` rather than a clock. **An entity absent from `prev` is not diffed at all** — that single rule is what keeps a first run, and a freshly created supatree, from announcing their initial state as news; there is deliberately no "seed the baseline" special case in the caller. `Decide(evs, state, opts)` is the equally pure notification policy: the `eventTier` table, a per-key cooldown, and focused-tab suppression. A *suppressed* event must not arm the cooldown, or looking away once silences the notification you were owed. Note the cooldown is not defending against a still-failing check repeating — a persisted baseline makes `Diff` edge-triggered, so that emits nothing — it covers a restart against a missing `last-status.json` and genuine flapping.

The watcher is spawned by `supacmd/start.go` **before** its `syscall.Exec`, since nothing after that line runs. It is `Setsid`-detached with stdio to `LogsDir()`, and its own exit condition is "no `st-` session remains" — without that it outlives every session and polls forever. That makes it session-scoped, so covering the hours when nothing is open is a launchd/cron `--once` entry rather than a longer-lived daemon.

It runs outside nono (it needs `osascript`) and therefore outside any zellij session, so focused-tab suppression must name the session explicitly: `zellij.FocusedTab(session)` → `zellij --session <name> action dump-layout`. Guard it with `zellij.SessionAlive` first: `dump-layout` sent to a server that is shutting down makes zellij panic, and the watcher only notices a dead session on its next tick. The watcher writes its own `watch.log` through a writer that rotates at 1 MiB to one `.1` generation, opened only by the election winner (a loser rotating would move the live watcher's file away); `spawnWatcher` sends raw stdio to `watch.out`. **The watcher is the only process outside the sandbox**, so it is the only one that can notify; anything sandboxed appends to `NotifyPath()` (`outbox/notify.jsonl`, under `NotifyLockPath`) and the watcher drains it — truncating, never removing — through the same `AppendEvents` + `Decide` path as its own diff — an outbox that bypassed the tier policy would be used as a way around it. Drain **before** `AppendEvents`: a board-tier event exists to be written down rather than delivered, so an outbox drained after the ledger write is an event the PM was told had been recorded and that nothing recorded.

**Dashboard (`dash/`).** `supatree dash` is a read-mostly Bubble Tea view over `Status`, opened in its own tab (`supatree.DashTab`, via `Workspace.OpenOrFocusCommandTab`) by `D` in the sidebar. Row text is built plain and styled last — `truncate` slices runes, so it must never run over a string that already carries ANSI escapes.

**Sidebar (`pkg/supatree/tui`).** Mirrors the workbench sidebar's live-sync + PR-fetch discipline: `reloadWithSelection()` re-reads `supatree.List` on `tea.FocusMsg`, every tick, and whenever `stateStamp` (stats only, every `stampInterval`: the trees' state dirs, `meta.yml`/`agents.yml`, member worktrees, `pms.yml`) changes — so a tree the PM or another tab created shows its members as soon as they land (pinning the cursor by row identity). Dirty markers come from `supatree.DirtyMembers`, one snapshot (`dirty.json`) that a single sidebar refreshes per round under a try-lock, not a `git status` per member per tab; and `fetchPRCmd(force)` goes through `FetchTargets`/`FetchPRs` and respects the persisted backoff (`Cache.InBackoff`) — this is what keeps the restart loop and per-tab sidebars from exhausting the gh quota. Its round runs inside `Cache.TryMutate` exactly as the workbench sidebar's does; see "The PR cache has exactly one writer path" above. The supatree workspace sets `SidebarActiveEnvVar: "SUPATREE_ACTIVE_TREE"` (tab name → `▸` "you are here" marker), and `supatree ls` must run with `tea.WithReportFocus()` for the focus re-sync to fire. `n` prompts for a tree name (blank = auto), first asking for a stack only when >1 is registered. `N` is the same flow for a review tree, with a pull-request prompt between stack and name: completed references are form-checked with `ParsePRRef` as you type (the trailing reference validated on completion or enter), and the `gh` lookups (`ResolvePRRefs`) run in the create `tea.Cmd`, never per keystroke; its placeholder is listed under Reviews (`creatingRev`). **The PM section leads `m.rows`**: `rebuildRows` always emits `rowPM` + `rowDivider` (`pmSectionRows`) before the first tree, even with no supatrees, so the empty state renders them above its hint. `rowDivider` joins `rowSubheader` as non-`selectable()`; the tree-scoped keys go through `selectedInTree()`, which is nil on the PM row, so fold/sync/delete/`a`/`m` never act on a tree named `""`. Its `✉N` badge is `PendingRequests` counted in a `tea.Cmd` (`refreshPMPendingCmd`) alongside the other background refreshes. `View` windows `m.rows` around the cursor (`viewport`) so long lists scroll instead of running off the pane, and `?` swaps the rows for `helpView()` (any key dismisses it).

**Folds are on disk, not in the model.** `supatree.UIState` (`uistate.go`, `<state>/ui.yml`) carries both fold maps, because one sidebar runs per Zellij tab and an in-memory map left every tab rendering a different shape of the same list. Both maps default to their zero value — a supatree is expanded unless listed collapsed, its repositories section collapsed unless listed expanded — so a name nobody has touched gets the intended default with no entry. Every change goes through `Model.persistUI`, which applies the mutation to the *on-disk* state under `UIStateLockPath()` (a peer tab's fold made in the meantime survives) and adopts the result; `reload()` re-reads it, which is how a fold made elsewhere arrives. Because `persistUI` adopts what it read back, a fold poked straight into `m.ui` is dropped by the next one — tests fold through `persistUI` too.

Two levels fold: `space` shuts the innermost section the cursor is in (the repositories list on a repo or section row, the supatree anywhere else), `h` shuts the repositories section first and only steps out to the supatree once it is already shut. The repositories header is its own `rowRepos` kind — selectable, unlike the `agents` subheader — and carries `prCounts`, one coloured glyph-and-count per PR status across the members. That badge is lifted onto the supatree row only while the whole supatree is folded, so it is never printed twice. `prGlyph`/`prStyle` are the single mapping from `github.PRStatus` to symbol and colour, shared with the per-member `prIcon`.

**The footer is not a log.** `updateNormal` clears `m.err`/`m.msg` on every key, mirroring the workbench sidebar: an `actionDoneMsg` error otherwise outlived the moment it described (a rejected supatree name sat under the next create prompt). The new-tree prompt validates as you type — `validateTreeName` checks `git.ValidateName` against the names already in `m.insts` rather than re-scanning the trees base, since it runs per keystroke, and `enter` on an invalid name keeps the prompt open instead of firing a create that would only fail. `supatree.New` still re-validates against disk.

**Focusing a running agent or PM is only a tab switch.** `OpenRootAgent` (unless `Wake`) and `OpenPM` first try `focusLive` — one pane listing, then `GoToTab` — with no lock, trust seeding, preflight or process-registry scan; only a tab that is not shown alive takes the full, locked open path. Those steps had put every switch behind any launch in the same tree. `ListProcs` judges every record from one `ps` (`agentExecs`).

**Enter is row-kind contextual.** The row sections carry different meanings and `openSelected` respects that: an agent row is a *process* (its `●`/`○` is liveness) so `enter` opens or focuses its tab via `OpenRootAgent`; a member row is a *place* reporting state (branch, dirty, PR) so `enter` calls `OpenMemberShell` — a plain `zellij.NewPane` at `repos/<alias>/`, outside nono because it is the user's own shell, and a pane rather than a tab because `<tree>:<alias>` is already the member *agent*'s tab name and a disposable shell needs no identity there. The member-scoped agent (`OpenMemberAgent`, nono allowing only that repo) moved to `a`, which reads as "give me an agent here" on every row — the tree-level name prompt on tree/agent rows, the repo-scoped agent on a member row. Don't collapse these back onto one key: the footer hint (`enter shell` / `enter open`, built from `m.selected()`) is what makes the split discoverable, so a new row kind needs its hint case too.

**Sidebar navigation.** Vim motions live in `updateNormal`: `j`/`k`, `ctrl+d`/`ctrl+u` (`halfPage`, sized from the `viewHeight` that `viewport` records each render), `G` (`gotoBottom`), `}`/`{` (`jumpTree` — next/previous `rowTree`), plus the two-key sequences `gg`, `zM` and `zR` driven by the `pending` prefix field (an unrecognized second key clears the prefix and falls through to the normal switch, so a mistyped `g` never swallows a command). Mouse handling is in `updateMouse`: the wheel calls `scrollBy`, which pans `m.scroll` and clears `m.follow`; `viewport` only drags the scroll offset to the cursor while `follow` is set, so a wheel-scrolled view survives the 30s tick reload. Every deliberate cursor move (`moveCursor`, `gotoTop`/`gotoBottom`, `jumpTree`, `setCollapse`, `selectByRow`) re-arms `follow` — but `clampCursor`/`reloadWithSelection` deliberately do not, or background reloads would yank the view back mid-scroll.

**Claude folder trust.** `OpenRootAgent` seeds `projects["<root>"].hasTrustDialogAccepted` in `~/.claude.json` via `sandbox.TrustDir` before launching. Claude asks "Do you trust the files in this folder?" once per directory and records the answer there — but a supatree root is shared by several agents, and each rewrites that whole file from the snapshot it read at startup, so an agent that started before the dialog was accepted writes the unaccepted entry back and the prompt returns forever. Seeding it before any agent starts means every process reads an already-trusted entry and writes it back unchanged. It is best effort (a failure is at most a warning), writes only when the flag is not already set, and resolves the `~/.claude.json` symlink so an atomic write lands on the real file instead of replacing the link. Workbench worktrees are one-agent-per-directory and do not need it.

**Agents.** Several agents share the supatree root but resume independently via session IDs (`Model.NewSessionArgs`/`ResumeSessionArgs`, `{session_id}` substituted by `sandbox.BuildAgentNonoArgs`). `supatree open [--agent <name>]` opens/resumes a root agent; `--repo <alias>` opens an agent scoped to one member (dir-based resume). Tab names: `<name>` for the `main` agent, `<name>:<agent>` otherwise.

**MCP tools** (`supatree mcp`, gated by `SUPATREE=1` except `docs`/`supatree_info`): `supatree_info`, `sync`, `rename_branches`, `create_pr`, `create_prs`, `pr_status`, `docs`. `pr_status` reports the `Status` rollup and refreshes through `FetchPRs` (forced past the staleness gate — an agent asking wants a current answer — but still under the lock and backoff). `create_pr`/`create_prs` refuse a still-city-name slug and (unless `force`) a repo whose dependencies have no PRs yet. Only `supatree init` registers this server (`claude mcp add supatree -s user`); skip it and a supatree session sees only workbench's tools. The **workbench** MCP tools (`create_pr`/`rename_branch`, gated by `WORKBENCH=1`) detect `SUPATREE=1` and redirect to these instead of dead-ending on the missing `WORKBENCH` env var. Branch slugs (`rename_branches`) share `git.ValidateName` — max 40 chars.

**Rename (`rename.go`).** `RenameBranchSlug` is phased so the tree is never half-renamed: every local `git branch -m` runs first and a failure part-way rolls the earlier ones back (`meta.Slug` derives `Member.Branch`, so a member left on the other slug falls outside its own tree and loses its PR and status); only then are meta + info written; only then does `--push` run, collecting per-member failures rather than aborting, since the rename has already been committed to meta.

**Conventions.** Reuse workbench packages — never fork them. `make ci` and the e2e script must stay green.

**e2e scripts: never pipe into `grep -q`.** Under `set -o pipefail`, `-q` exits on the first match, the Go process writing to the pipe dies of SIGPIPE (exit 141), and the pipeline fails even though the assertion passed. Use plain `grep … >/dev/null`.

## Before pushing / creating a PR

Run `make ci` (fmt + lint + vet + test) and fix all issues. The linter (`golangci-lint`) enforces errcheck, exhaustive switch, noctx, prealloc, staticcheck and more — fix warnings, do not suppress them.

**Supatree's conventions live in info.md, not in stacks (`agentsmd.go`).** A stack's `AGENTS.md` is the human's file and supatree never regenerates it, so anything supatree puts there is frozen at scaffold time — #6 was an agent reading a copy that predated named PMs. The scaffold is therefore only a pointer to `.supatree/info.md`, which is rendered on every create, sync and rename. Older stacks are recognised by `priorAgentsMD` — the length and SHA-256 of every scaffold that shipped — and `UpgradeAgentsMD` replaces exactly those bytes, keeping what follows; anything else is reported by `doctor`, never rewritten. **Changing `scaffoldAgentsMD` means registering the outgoing one**: `TestScaffoldAgentsMDIsRegistered` pins its sum and says what to add.
